# Git и SVN: сравнение

## 1. Почему в Git ветвление «дешёвое», а в SVN «дорогое»?
В Git ветка — это лёгкий указатель на коммит, поэтому создать её можно мгновенно, без копирования файлов. В SVN ветка — это отдельная копия каталога в репозитории на сервере, поэтому создание и слияние занимают больше времени и требуют больше ресурсов.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN — централизованная система: история хранится на сервере, а у разработчика только рабочая копия. Коммит отправляется прямо на сервер, поэтому без соединения его не сделать. В Git репозиторий полностью хранится локально, коммиты делаются офлайн, а на сервер отправляются позже через push.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Проекты с большими бинарными файлами и строгим контролем доступа к каталогам.
- Команды со старой инфраструктурой, где уже выстроены процессы вокруг SVN.
- Когда нужна простая линейная модель без ветвления и rebase.
